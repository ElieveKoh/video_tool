1. 프론트엔드 및 렌더링 최적화 (가장 시급한 병목) 문제점: Streamlit은 사용자가 상호작용(버튼 클릭, 텍스트 입력 등)을 할 때마다 코드를 위에서 아래로 재실행(Rerun)합니다. 현재 구조는 매 실행마다 무거운 UI 작업이 반복되는 치명적인 구조적 문제를 안고 있습니다. 과도한 DOM 감지 (MutationObserver) 제거: video_converter_app.py에 작성된 MutationObserver는 부모 body의 childList 변경을 감지하여 applyTheme()을 호출합니다. Streamlit은 UI가 업데이트될 때마다 DOM 트리를 수시로 파괴하고 재생성합니다. 이는 무한 루프에 가까운 테마 적용 스크립트 실행과 브라우저 리플로우(Reflow)를 유발해 앱을 심각하게 느려지게 만듭니다. 개선안: MutationObserver와 setTimeout을 제거하십시오. Streamlit의 기본 테마 시스템(.streamlit/config.toml)을 활용하여 다크/라이트 모드를 제어하거나, 사용자 정의 CSS 변수를 앱 로드 시 한 번만 주입하는 방식으로 변경해야 합니다. 대형 인라인 CSS 로드 방식 변경: 매 리런마다 대형 st.html("") 문자열을 주입하면 파싱 비용이 지속적으로 발생합니다. 글래스모피즘(블러, 백드롭 필터) 요소까지 더해져 GPU 렌더링 부담이 큽니다. 개선안: 정적 자산 서빙을 활용해 외부 .css 파일로 분리하고 이를 캐싱하여 불러오거나, 꼭 필요한 레이아웃 CSS만 남기고 무거운 시각 효과는 최소화하는 것이 좋습니다. 목업 파일(ui.html) 분리: 앱 구동에 직접 관여하지 않는 114KB짜리 대형 파일(중복된 CDN 및 폰트 호출 포함)이 프로젝트 루트에 있습니다. 이는 런타임에 영향을 주진 않지만, 패키징 및 유지보수 시 혼란을 줍니다. .claude/plans/나 별도의 docs/ 폴더로 이동시키는 것을 권장합니다. 2. 백그라운드 작업 및 UI 블로킹 방지 문제점: FFmpeg 및 yt-dlp 서브프로세스 실행이 메인 스레드에서 동기적으로 돌고 있을 가능성이 큽니다. 비디오 인코딩처럼 수십 분이 걸릴 수 있는 작업이 메인 스레드를 잡고 있으면 Streamlit UI는 완전히 멈추게(Freeze) 됩니다. 비동기 처리 또는 스레딩 도입: 현재 import threading만 되어 있고 사용처가 없다면 이를 적극 활용해야 합니다. 긴 작업은 별도의 백그라운드 스레드로 넘기고, 메인 Streamlit 앱은 st.session_state를 통해 진행률(Progress) 데이터만 주기적으로 읽어와 UI를 업데이트하도록 구성해야 합니다. Streamlit Fragment 활용 (버전 1.37 이상): 사용 중이신 Streamlit 버전이 1.48.1이므로 @st.fragment 데코레이터를 사용할 수 있습니다. 진행률 바나 상태 텍스트를 업데이트하는 함수에 프래그먼트를 적용하면, 전체 페이지를 리런하지 않고 해당 UI 영역만 가볍게 새로고침하여 퍼포먼스를 크게 높일 수 있습니다. 3. 코드베이스 모듈화 (유지보수성) 문제점: video_converter_app.py 파일 하나가 약 117KB에 달합니다. UI 레이아웃, CSS 주입, FFmpeg CLI 제어, 다운로드 로직이 한 파일에 섞여 있으면 추후 기능 추가나 디버깅이 매우 어려워집니다. 관심사 분리 (Separation of Concerns): 코드를 기능별로 분리하는 것을 강력히 권장합니다. app.py (메인 UI 뼈대 및 라우팅) utils/video_processor.py (FFmpeg/FFprobe 서브프로세스 로직) utils/youtube_downloader.py (yt-dlp 로직) components/ui_styles.py (스타일 및 테마 주입 로직) 4. 외부 바이너리 의존성 관리 문제점: yt-dlp와 ffmpeg를 CLI 바이너리로 호출하고 있습니다. 특히 yt-dlp는 YouTube의 알고리즘 변경에 대응하기 위해 수시로 업데이트되어야 합니다. 자동 업데이트 로직 추가: 앱 내부에 yt-dlp 바이너리 업데이트 기능(yt-dlp -U를 서브프로세스로 실행)을 버튼 형태로 제공하여, 다운로드 오류 발생 시 사용자가 직접 최신 버전으로 갱신할 수 있도록 하면 유지보수 문의를 크게 줄일 수 있습니다
